# Benchmark artifacts

For extending testing beyond Filesystem, see [the multi-service benchmark process](MULTI_SERVICE_BENCHMARK_PROCESS.md). It covers the seven remaining paper domains, Docker isolation, official setup sources, adapter work, and matched A/B evaluation.

`paper-protocol-filesystem.json` and its Markdown summary are generated by:

```powershell
.\.venv\Scripts\python -m toolatlas.paper_benchmark
```

The harness adopts the evaluation shape used by ToolAtlas (arXiv:2607.11126):

- disjoint 1:2 train/test tasks;
- frozen memory before evaluation;
- same-environment and cross-environment splits;
- four runs per task;
- programmatic verification;
- pass@1 and pass@4;
- inference cost separated into provider calls, memory calls, total MCP calls,
  latency, and offline memory-construction cost.

This repository currently runs a deterministic read-only Filesystem control. It
does **not** reproduce the paper's full MCPMark and MCP-Universe evaluation over
eight services, three agent frameworks, and three model backbones. The result
files intentionally carry that limitation in `claim_scope`.

`results/mcpmark/filesystem-smoke-nvidia-kimi-k3.json` is a separate official
MCPMark Docker smoke result generated from the public MCPMark runner:

```powershell
python3 -m pipeline --mcp filesystem --models nvidia-kimi-k3 --exp-name toolatlas-mcpmark-smoke --tasks file_property/size_classification --k 1 --timeout 900
```

That artifact is baseline-only (`is_toolatlas_assisted: false`). It confirms the
official MCPMark Filesystem path and verifier work locally with the configured
NVIDIA OpenAI-compatible endpoint, but it must not be cited as a ToolAtlas
tool-call reduction result.
